# Plan: Swap Read API client with RPC fallback (tested on localhost against the devnet)

Repo: `C:\github\quantumswap\quantumswap-web-app` (TypeScript, Vite, vitest, Playwright, no framework; DOM via `src/ui/dom.ts` `el()`, state via `src/ui/store.ts` `createStore`). First implementation step: copy this plan to `docs/plans/swap-read-api-client.md` in that repo (user decision).

## Context

The quantumscan repo now serves a per-DEX **Swap Read API** (`api/swap-api.yaml`, 10 GET operations under `/swap/v1`, running on this machine's devnet at `http://127.0.0.1:8182`, CORS `*`, no key). The web app today has **no HTTP surface**: every read is an `eth_call` through the browser-extension provider (`src/lib/extensionProvider.ts`), so browsing needs a connected wallet, the route finder fans out up to ~65 `factory.getPair` calls per uncached quote, and the positions page does a serial `balanceOf` over every registry pair. The prior audit found 30 of 36 read call sites are market state the API covers.

Goal: the app reads market state (pairs, reserves, LP supply, routes, token facts, LP positions, pairs created) from the Swap Read API, with the **existing RPC path kept as a transparent fallback** whenever the API is unavailable/unhealthy/does not index the active DEX; wallet state (balances, allowances), transactions, receipts, deadlines and the exact-out fee pre-flight stay on RPC. The API URL is configured beside the embedded RPC URL, overridable per release, and the whole thing is exercised on localhost against the devnet with tests that hit **all 10 API operations**.

**User decisions (fixed):**
- Built-in default `SWAP_API_URL = "https://api.quantumswap.com"` (chain.ts) — also the production CSP origin.
- Extension stays required: `main.ts:102-105` (no-provider → install modal, stop) is **unchanged**. The API removes the *connected-wallet* requirement for reads (the extension-installed-but-not-connected state browses via the API); it does not remove the extension requirement.
- Quote when a wallet is connected = **router RPC `getAmountsOut/In` on the API-chosen path** (chain truth for `amountOutMin`); local constant-product math over API reserves is only the not-connected / router-failed "estimate".
- Plan doc lives in the web app repo.

**Facts that shape the design (verified against the live devnet API):** devnet dexId `quantumswap-beta2` = factory `0x4936ede4…1b0e19ae876b35e7b0d25ad7a319`, router `0x957320a8…`, WQ `0x761e72c4…`, 75 pools; tokens LIO `0x6467cdc3…`, TIG `0x6555fa08…`; pools LIO-WQ `0x0b8610ae…`, TIG-WQ `0xc4da927b…`, LIO-TIG `0x114dbd57…`; funded/creator account `0x1a846abe…049aec6` holds LP in all 75 pools; second dexId `quantumswap-preflight` (2 pools). Chain id 123123 = app `CHAIN_ID`. **Every devnet token fact has `decimals: null`** (explorer could not decode them there; mainnet approved tokens return 18) — the client must never take decimals from the API for amounts: use the built-in/imported `TokenInfo`, then RPC `decimals()` when a provider exists, else display-only "assumed 18" flag. API addresses are lowercase; compare with `toLowerCase()` (existing convention).

## Design

### 1. Config — beside the RPC URL
- `src/config/chain.ts`: `export const SWAP_API_URL = "https://api.quantumswap.com";` next to `BLOCK_EXPLORER` (:13); rework that constant's "never fetched" comment into a short "network endpoints" block that also documents `main.ts:85`'s RPC `Config` URL (transport-less) vs the API (fetched).
- `src/config/releases.ts`: `Release.apiUrl?: string` (optional; built-in release omits it → default). `loadReleases()` validates it with a new `sanitizeUrl` (invalid → field dropped, release kept); persisted in `qs.releases.v1`; `addCustomRelease(name, wq, factory, router, apiUrl?)`; new getter `swapApiUrl(): string = currentRelease().apiUrl ?? SWAP_API_URL`. `applyRefreshSideEffects()` additionally resets the market-data store (re-probe).
  - **Superseded (2026-08-30):** `Release.apiUrl` and `Release.dexId` are now required strings on every release (built-in: `SWAP_API_URL` / `SWAP_API_DEX_ID`; the add form prefills those defaults). An empty string means the Swap Read API is off for that release (`marketStore.status === "disabled"`, extension RPC only); the factory-address matching fallback was removed, and `probeSwapApi()` only accepts a dexId whose `factoryAddress` on the API equals the release's factory. Persisted releases without the keys load with the defaults.
- `src/lib/sanitize.ts`: `sanitizeUrl(input): string | null` — `new URL()`, protocol ∈ {http:, https:}, no credentials/query/hash, ≤ 200 chars, returns origin + pathname without trailing slash.
- `src/views/releases.ts`: optional "Swap Read API URL" field in the add-release form; release card shows the API line ("Indexed 75 pools · block N" / "Not indexed by API" / "API unavailable") from the market store.
- `index.html:24` CSP: `connect-src 'self' https://api.quantumswap.com http://127.0.0.1:8182 http://localhost:8182` (loopback entries are inert elsewhere and are what the devnet/e2e uses; a custom `apiUrl` on any other origin is blocked by CSP → fetch throws → RPC fallback — documented). `README.md` Security section updated accordingly.

### 2. Client — `src/lib/swapApi.ts` (pure HTTP, no app state)
- Typed DTOs mirroring `swap-api.yaml` (DexList/DexInfo, DexStatus, TokenFacts, TokenList, Pool, PoolList, RouteResponse{paths[].hops, pairs, tokens}, PairLookup, AccountPositions).
- `createSwapApiClient(baseUrl)` → 10 methods: `dexes()`, `status(dex)`, `token(dex, addr)`, `tokens(dex, page)`, `pools(dex, {page, sort, token})`, `pool(dex, pair)`, `route(dex, from, to, k)`, `pair(dex, a, b, account?)`, `positions(dex, acct)`, `pairsCreated(dex, acct, page)`. `fetch(url, {signal: AbortSignal.timeout(4000), headers: {accept: "application/json"}})`; path params validated with `ADDRESS_RE` / `^[A-Za-z0-9_-]{1,64}$` **before** the request.
- `class SwapApiError { kind: "network"|"timeout"|"http"|"parse"|"not-found"|"unknown-dex"; status? }`. 404 on token/pool = `not-found` (a data answer); 404 whose message is `dex not found` = `unknown-dex`.
- Per-DTO sanitizers reuse `src/lib/sanitizeResponse.ts` (`toBigIntOrNull` for every HexQuantity, `sanitizeSymbol/Name`, `sanitizeDecimals` only when non-null, `sanitizeAddressResponse`, `toNumberOrNull`); add object-shaped `sanitizeApiReserves({token0, token1, reserve0, reserve1})` beside the tuple-shaped `sanitizeReserves`. Malformed required field → `SwapApiError("parse")`.

### 3. Facade — `src/lib/marketData.ts` (the only module views/registry/routeFinder call for market reads)
- `marketStore = createStore<{status: "unknown"|"ok"|"unavailable"|"no-dex"; dexId; indexedBlock; lagBlocks; degraded; apiUrl}>`.
- `probeSwapApi()`: `GET /dexes`, map `currentRelease().factory.toLowerCase()` → `dexId`; `ok` / `no-dex` / `unavailable`. Called in `main.ts` in parallel with `initWallet()` (after `initReleases()`), and from a `releaseStore` subscription when the active release / factory / apiUrl changes.
- Circuit breaker: 2 consecutive `network|timeout|http≥500|parse` failures → `unavailable`, 30 s cooldown, then a cheap `/{dexId}/status` re-probe (also refreshes `lagBlocks`/`degraded`). `degraded || lagBlocks > 20` → still used, but `marketStore.degraded = true` (slim shell banner; swap quote labelled "estimate").
- `apiAvailable() = status === "ok"`; `canRead() = apiAvailable() || walletStore.status === "connected"` — replaces the connected-wallet gates in the read-only views (extension presence is still required by `main.ts`).
- Every read is `apiFirst(apiFn, rpcFn)`: API when `ok`; on `SwapApiError` other than `not-found` → record failure and run `rpcFn` **if a wallet is connected**, else throw `MarketUnavailableError` (views render "Connect your wallet to load" / empty state, no console error). Reads: `getPools(page, sort, token?)`, `getPool(pair)`, `lookupPair(a, b, account?)`, `getTokenFacts(addr)`, `listIndexedTokens(page)`, `getPositions(account)`, `getPairsCreated(account, page)`, `getRoutes(from, to, k)`, `getDexStatus()`. RPC bodies are today's code moved out of the views (pairDetail's 4 reads, positions' balanceOf loop, poolExplorer's per-row `getReserves`, `readTokenMetadata`, `factory.getPair`). Each API pool result is absorbed into the registry via `mergePair({discovered: true})` so search / `tokenSymbol` / tokenDetail keep working unchanged. `invalidate()` clears memos (called on txStore confirmations, replacing poolExplorer's private `reservesCache` invalidation).

### 4. Call-site rewiring
- `src/lib/pairRegistry.ts`: `resolvePairAddress` body → `lookupPair`; `discoverKnownPairs()` → one `getPools(1, "liquidity")` when API ok, else the old O(n²) loop; `discoverAllFromFactory(limit)` → page through `/pools` when API ok, else the old factory walk. `mergePair/findPairRecord/absorbDiscoveredPair` unchanged.
- `src/lib/routeFinder.ts`: `findBestRoute` / `findBestRouteExactOut` keep signatures; `RouteResult` gains `source: "router" | "api-estimate"` and `indexedBlock?`. (a) API ok → `getRoutes(A, B, k=3)`; each path's hops → token path `[A, hop1.tokenOut, …]`; evaluate locally with `quoteMath.getAmountOut/getAmountIn` chained over the returned reserves (orient by `token0/token1`); empty `paths` → no route; all paths yield 0 / exceed reserves → `InsufficientLiquidityError`; pick best. (b) If wallet connected → `router.getAmountsOut/In` on the chosen path: success → `source: "router"` (chain truth); provider error → keep the estimate. (c) API unavailable → today's `findShortestPath` + router (connected wallet required; unchanged). `clearRouteCache` also clears the API route memo (keyed dexId+A+B+routeVersion, 15 s TTL). `quoteMath.ts` header comment updated (its `getAmountOut/In` become live).
- `src/views/swap.ts`: the two "Connect your wallet to fetch a live quote" gates (:397, :452) → `canRead()`; show a "Quote: estimated from indexed reserves · block N" row when `source === "api-estimate"`; `walletStore.subscribe` also calls `refreshQuote()` so connecting upgrades to the router quote. `routePath` reuse at tx time (:427), the exact-in `SupportingFeeOnTransferTokens` + `minWithSlippage` floor, and the exact-out pre-flight `eth_call` (:437-459) are **untouched**; API-sourced `quotedOut` only ever becomes `amountOutMin` through that same floor.
- `src/tokens/tokenList.ts`: `readTokenMetadata(address)` → API-first (`not-found` → RPC; no wallet → throw as today); `refreshApprovedTokenMetadata()` → API for name/symbol (404 is normal on devnet), RPC `decimals()` only when connected; keep the in-place mutation of `APPROVED_TOKENS` (identity matters for `DEFAULT_PAIR_TOKEN_A/B`); `checkImport` unchanged; `readTokenBalance` stays RPC.
- Views: `poolExplorer.ts` (table from `getPools` with pager + sort; gates `:149/:164` → `canRead()`), `pairDetail.ts` (`getPool` + `lookupPair(…, account)` for LP balance), `positions.ts` (`getPositions(account)` API else the serial loop; new "Pools you created" card from `getPairsCreated`; gate `:44` keeps requiring an account — the extension is required anyway), `addLiquidity.ts` / `createPair.ts` (`resolvePairAddress` + `lookupPair` reserves; gates `:99/:58` → `canRead()`, tx CTAs stay connect-gated), `removeLiquidity.ts` (pool via `getPool`; LP balance via RPC when connected, API `accountLpBalance` as display fallback), `tokenDetail.ts` (`getTokenFacts` + `getPools(1, "liquidity", address)` replaces the registry-only filter), `tokenExplorer.ts` (new "Indexed on this DEX" list via `listIndexedTokens`), `search/search.ts` `probeAddress` (`getPool` then `getTokenFacts`, RPC fallback), `ui/components/appShell.ts` (API status pill from `marketStore`).
